# translate-ime 详细使用流程

这份文档按「拿到程序 → 装好 → 第一次启动 → 确认生效 → 日常打字 → 挂起/退出 → 开机自启 → 出问题怎么查」的顺序写，
每一步都写清楚**该看到什么**，看不到就按最后一节的对照表查。

先说清楚它到底是什么，后面所有流程都建立在这个前提上：

> **它不是 Windows 输入法。** 它没有注册 TSF 文本服务、也没有装键盘布局，所以
> **Win+Space 和任务栏语言栏里永远不会出现它** —— 没有「选中它」这一步。
> 双击 `run.bat` 之后，它就在后台挂一个全局键盘钩子，把字母接过来自己处理，
> 弹出候选窗、自己把汉字打进目标窗口。微软拼音照旧装在系统里，只是打字时收不到字母。

---

## 0. 最快上手（三行版）

```bat
run.bat                 :: 双击它 = 后台常驻启动，关掉黑框不影响
双击后打开记事本，敲 nihao      :: 应该出现候选窗，空格上屏「你好」
Ctrl+Alt+Q                     :: 退出（热键可改，见第 7 节配置）
```

其余的细节都在下面。

---

## 1. 准备（只做一次）

1. 确认系统是 Windows 10 / 11（托盘、UI 自动化都依赖 Win32）。
2. 依赖和虚拟环境（项目目录里已经有 `.venv` 就跳过）：

   ```bat
   cd /d D:\dsh-work\杂活\translate-ime
   python -m venv .venv
   .venv\Scripts\python.exe -m pip install -r requirements.txt
   ```

3. （可选，但想要「翻译」就得做）配置 API key。两种方式二选一：
   - 在 `config.json` 里填 `api.api_key`；
   - 或者设环境变量 `DEEPSEEK_API_KEY`。

   没配也能用：拼音照常，译文行会走离线词表，并在面板/日志里说明「翻译走离线词表（没配 API key）」。

4. （可选）生成配置文件模板：

   ```bat
   run.bat --init-config
   ```

   已存在 `config.json` 时**不会覆盖**，只提示「配置文件已存在，没动它」。

## 2. 第一次启动

### 2.1 启动

双击项目根目录的 `run.bat`，或等价地：

```bat
run.bat --background
```

> 这一节起，命令都用 `run.bat` 开头。**不要直接敲 `python main.py ...`** —— 系统里的
> `python` 一般没装 `jieba` / `pypinyin`，会满屏 `[FAIL] 依赖`；`run.bat` 会自己找
> `.venv\Scripts\python.exe`，并把参数原样转给 `main.py`。

### 2.2 应该看到什么

1. 一个黑框（cmd）弹出来，打印几行字：

   ```
   [main] 配置来自 D:\dsh-work\杂活\translate-ime\config.json
   [daemon] 已在后台常驻（无窗口）。日志见 D:\dsh-work\杂活\translate-ime\translate-ime.log
   [daemon] 已就绪：钩子装上了，现在可以打字了。
   [daemon] 退出：托盘图标右键 -> 退出，或按 Ctrl+Alt+Q。
   [main] 已在后台启动（没有窗口，关掉这个黑框不影响它）。
   [main] 想操作它：再双击一次 run.bat，会弹出一个控制面板。
   ```

   第二行到第三行之间会**停一两秒**——那是在等实例建好拼音索引、把键盘钩子装上。
   以前这里不等，父进程 1.5 秒就报「已在后台启动」，而实例其实还没接管键盘：
   这段时间里你打的拼音会原样变成英文字母，候选窗一次都不出现（第 88 轮修的就是这个）。
   现在只有真的报出 `[daemon] 已就绪：钩子装上了` 才算启动完成；等不到它会明确说
   「还没就绪」，不会假装成功。

2. 黑框**几秒内自己关掉**。关掉它不影响输入法 —— 真正的实例是 `pythonw.exe`，没有窗口。

3. 第一次启动会花约 2 秒，从 jieba 词库反向构建拼音索引（约 56,000 个键），缓存在
   `pinyin_index.pkl`；以后启动是毫秒级。

4. 屏幕上会弹出**启动引导**（约 7 秒），7 行内容，包含「语言栏里没有它是正常的」「快捷键」等。
   这段引导只出现在**实例自己的日志**里，不会打进上面那个一秒就关掉的黑框（黑框里只有父进程
   那几行）。想慢慢看：`run.bat --foreground`，或者翻日志 `translate-ime.log`。

5. 右下角托盘区会出现一个图标（`translate-ime`），右键能看到「挂起 / 英文直通 / 退出」等菜单。

### 2.3 任务管理器里为什么可能有两个 pythonw.exe

如果虚拟环境的 `pythonw.exe` 是「启动转发器」，任务管理器里会看到：

- 一个约 5～6 MB 的 `pythonw.exe`：venv 的转发器；
- 一个约 70 MB 的 `pythonw.exe`：真正的实例。

这不是双开，退出时两个会一起消失。判断谁在干活看状态文件里记的 `pid`
（项目根下的 `translate-ime.status.json`），以及 `--doctor` 的 `[0]` 段。

## 3. 确认它真的在接管

打开**记事本**（不要用「以管理员身份运行」的窗口），敲：

```
nihao
```

应该看到：

- 一个深色的候选窗贴在光标下方，显示「你好 / 你号 / 你灏 …」；
- 按 `空格` 上屏「你好」；
- 候选窗自动收起。

再验证几个关键键：

| 操作 | 应该发生什么 |
| --- | --- |
| 按 `Tab` | 候选窗从「中文行」切到「译文行」（没配 key 时是离线词表）；翻译关着（`translate.enabled=false`）时切不过去，会提示先打开它 |
| 按 `1` | 直接上屏第 1 个候选 |
| 按 `Esc` | 清空当前拼音，什么都不上屏 |
| 按住 `Shift` 再敲字母 | 原样输出大写字母（不弹候选） |
| 600 毫秒内点一下 `Shift` | 切到「英文直通」，字母原样透传；再点一下切回 |

**如果什么都没发生**，不要反复双击 run.bat —— 先跳到第 9 节「自查流程」。

## 4. 日常打字

### 4.1 拼音与选词

| 按键 | 作用 |
| --- | --- |
| 字母 | 打拼音 |
| `'` | 打拼音时按下去不会进文档（被当成分词符吞掉）；候选仍按整串拼音算，`xi'an` 与 `xian` 的候选完全一样 |
| `←` `→` / `↑` `↓` | 在当前行里选候选 |
| `1` – `9` | 直接选第 N 个候选上屏（改选会被自学习记住） |
| `空格` / `回车` | 上屏当前高亮候选 |
| `Esc` | 清空当前拼音缓冲 |
| `Backspace` | 退格；缓冲已空时透传给目标程序 |

缓冲为空时 `Tab` 会**透传**给目标程序（否则编辑器里打不出制表符）；要切语言用 `Ctrl+Alt+L`，或者先打字再按 Tab。

> 候选窗最下面那行提示里的「换语言」写的是**真正注册上**的那个键。你要是把 `hotkeys.toggle_default` 配成 `"l"` 这种（没有修饰键的打字键，会被拒绝注册）或留空，那一段就**不会出现**，而不是照抄一个按了没反应的键（第 115 轮修）。

> 关于 `'`：它只是「显式分音节」的写法，**不会改变候选**（`'` 会被吞掉、不进文档）。
> 早先这里写着「`xi'an` → 西安」，那是错的 —— 词库里根本没有「西安」这个词，
> 所以 `xi'an` 和 `xian` 的候选一样，都是「先 / 县 / 现 …」。第 94 轮改成了实话。

### 4.2 中文 / 英文直通

- **点一下 `Shift`**（松手在 600 毫秒内）：在「拼音 → 中文」和「英文直通」之间切换。
  直通模式下所有键原样透传，`Shift+字母` 照样大写。
- **按住 `Shift` 超过 600 毫秒**：按普通 Shift 处理，不切换。
- `Ctrl+Alt+L`：切换默认上屏语言（中文 ⇄ 译文），相当于按 Tab；翻译关着（`translate.enabled=false`）时切不过去，会提示先打开它。

### 4.3 翻译

- 先打拼音，按 `Tab` 切到译文行，选词后上屏 —— 上屏的是译文。
- `Ctrl+Alt+Space`：一键直译上屏（跳过 Tab 和选词，直接注入最佳译文）。
- 没配 API key 时走离线词表；这个词不在词表里会在候选窗里说明原因。
- 翻译关着（`translate.enabled=false`）时，译文行只显示「翻译已关闭」，按空格会退回中文，并在候选窗里说明原因（不会悄悄变回中文）。

### 4.4 挂起 / 恢复

按 `Ctrl+Alt+Z`（热键可改）：

- 挂起后，所有按键原样透传，手感立刻还给系统输入法（微软拼音这时收得到字母）。
- 再按一次恢复。
- 挂起时**点 Shift 不会恢复**（Shift 单击在挂起状态下按设计不响应），只认 `Ctrl+Alt+Z` 或控制面板菜单。

### 4.5 退出

- `Ctrl+Alt+Q`；
- 或者右键托盘图标 → 退出；
- 或者再双击一次 `run.bat`（第二个实例会变成控制面板）→ 菜单里选退出；
- 或者任务管理器结束那个约 70 MB 的 `pythonw.exe`（不推荐，会留下状态文件，下次会自愈）。

## 5. 第二次启动 = 控制面板

实例已经在跑时，再双击 `run.bat` 不会起第二个实例，而是打开一个**控制面板**。它读的是运行中实例写下的状态文件，所以显示的是**那个实例**的实况（下面是一份真实输出，数字随你的使用而变）：

```
[main] 配置来自 D:\translate-ime\config.json

== translate-ime 已经在跑了 ==

  进程号     17236
  输入法     已启用
  输入模式   拼音
  上屏语言   中文
  托盘图标   已装上
  开机自启   未开启（跑 run.bat --autostart 打开）
  自学习     还没记住任何词（用数字键改选候选就会记住）
  翻译       离线词表（没配 API key） · 请求 0 次，命中缓存 0 次
  键盘钩子   收到过 42 个有效按键（最近 刚刚）
  候选窗     显示过 12 次 · 最近 534x230+120+200（在显示器上）
  日志       D:\translate-ime\translate-ime.log
  配置文件   D:\translate-ime\config.json （另有 45 个选项没写，正在用默认值）
```

有时还会多出一行 `实例提示` —— 那是常驻实例最近一次想跟你说的话。最常见的情况是：你在这里选了 `3) 换默认上屏语言`，但 `translate.enabled` 是关的，切不过去，实例会写明原因（第 105 轮加的行）：

```
  实例提示   翻译关着（translate.enabled=false）—— 切不到译文
```

如果这个控制台是交互式的（有真终端），会进入菜单 —— 一共 7 项，**按数字选**：

```
  1) 挂起 / 恢复输入法   2) 英文直通 开 / 关   3) 换默认上屏语言（中文 ⇄ 译文）   4) 在候选窗上显示使用帮助   5) 打开日志文件   6) 打开配置文件
  7) 退出 translate-ime          0) 什么都不做
  选择：
```

> `3) 换默认上屏语言` 和 `7) 退出` 不是同一个键。早先这里把菜单写成三项、还把第三项说成「退出」，是错的（第 95 轮改成实话）。

非交互（比如被脚本调用、stdin 不是终端）时会打印完状态、返回退出码 **3** 就走，不会卡住。把 stdin 重定向成 `NUL`（`.venv\Scripts\python.exe main.py < NUL`）也算非交互：Windows 上 `isatty()` 对 NUL 会返回真，程序会先进菜单、读不到输入后再按非交互收工，同样返回 3（第 95 轮修）。

### 5.1 不小心连按了两下 `run.bat`

不会起两个实例，也不会报错。抢到单实例锁的那一份正常常驻；另一份会打印一句「已经有一个 translate-ime 在跑了（pid …），这次不再启动第二份」，退出码 0，窗口直接关掉（第 106 轮修 —— 以前这里会报「后台启动失败（退出码 1）」并让 `run.bat` 停下来等你按键）。

```bat
[daemon] 已经有一个 translate-ime 在跑了（pid 12364），这次不再启动第二份。
[main] 想操作它就再双击一次 run.bat —— 会弹出一个控制面板。
[main] 日志：D:\translate-ime\translate-ime.log
```

> 开机自启和手动双击撞在一起时，看到这两行是正常的，不用管。

### 5.2 用浏览器改快捷键和 API key（Web 控制板）

不想手改 `config.json`，用这个：

```bat
run.bat --web                  :: 默认打开 http://127.0.0.1:8765/
run.bat --web --web-port 9000  :: 换端口（被占用时用）
run.bat --web --no-browser     :: 只起服务、不自动开浏览器
```

浏览器里能做四件事：

1. **改快捷键**：点某一行后面的「按一下」，然后直接敲你想要的组合键。捕获时会**吞掉这一下**：前台程序收不到它，常驻实例也不会把它当成真热键执行 —— 所以你按当前生效的 `Ctrl+Alt+Q` 也不会把输入法退掉；抓到就立刻收工，之后照常打字（第 109 轮修：以前既不吞键、还会因为解包写错而直接 500）。
   - 裸字母（`q`）、只有 `Shift` 的组合（`shift+q`）会被**拒绝并说明原因**：它们会在打字时误触。
   - 带两个主键的写法（`ctrl+q+w`）也会被拒绝，不会只取前半截。
2. **改 API key / provider / model / base_url**：key 只会以 `********` 的形式回传到浏览器（它不会再次出现在明文的页面里）。**留空 = 不改**；想清掉得点「清空」。
3. **一键让实例做事**：重载配置 / 挂起恢复 / 换默认上屏语言 / 退出 —— 和托盘菜单、控制面板走的是同一个收件箱。
4. **看当前状态**：实例在不在跑、有没有挂起、最近一次重载为什么失败；实例**拒绝**了你点的动作时，顶上会多出一条黄色的「实例提示：…」写明原因（比如 `翻译关着（translate.enabled=false）—— 切不到译文`）。第 105 轮给控制台面板加过同一行，第 110 轮才轮到网页这边 —— 以前只闪一下候选窗上的提示条，页面上看起来就是「点了没反应」。

保存后的行为：

- **热键、key、provider、model、base_url 立刻生效** —— 实例会重读配置，不用重启。面板的「配置重载」一行会显示重载过几次。
- 需要重启才生效的选项（`pinyin.min_freq` / `pinyin.max_word_len` / `pinyin.dict_cache` / `output.log_file` / 候选窗外观）保存时会单独提示。**如果你这次只改了这类选项，回执会直接说「其中 N 项要重启实例才生效」，不会说「不用重启」** —— 拼音索引是在启动时建进内存的，热重读换不掉它（第 113 轮修：以前只改 `pinyin.min_freq` 也会回「不用重启」，可实际一点没生效）。
- **如果现有 `config.json` 读不懂（比如编辑器存到一半、少了个括号），它会拒绝保存**，并把那份文件一个字节都不动地留着 —— 不会拿默认值把你原来的热键和 key 一起盖掉（第 108 轮修）。这时页面顶上还会红字说明「下面显示的是**程序默认值**，不是你的配置」，「保存并同步」也是灰的；把文件修好（或删掉）再点「重新读取」就会恢复（第 114 轮修：以前页面会把默认值当成你的配置，一句提示都没有）。
- **如果常驻实例用的不是这份配置**（比如实例是双击 `run.bat` 用默认 `config.json` 起的，而你是用 `run.bat --web --config 别的.json` 打开的面板），保存会照常写盘，但**不会**宣布「已同步」：页面顶上会红字提示「不同步：实例用的是 …」，保存回执里的 `synced` 是 `false`。两种改法：把控制板也指向实例那一份，或者退出实例后用你改的这份配置重启（第 109 轮修）。

安全边界：只监听 `127.0.0.1`，局域网里的其他机器连不上；写操作还要带上页面里的随机门票（`X-T-IME-Token`，每个进程一张），别的网站没法替你点按钮；没有登录口令（它是本地工具，和 `--doctor` 一样只服务你自己）。用完之后 Ctrl+C 或直接关掉那个控制台就行，**不会影响已经在常驻的实例**。

## 6. 常驻与开机自启

### 6.1 常驻两种形态

| 命令 | 效果 |
| --- | --- |
| `run.bat`（参数原样转给 main.py，所以带 `--background` 一样） | 后台常驻，没有窗口；关掉黑框不影响 |
| `run.bat --foreground` | 前台运行，日志同时打到控制台，方便盯着看 |

### 6.2 开机自启

```bat
run.bat --autostart          :: 写入当前用户的开机启动项（HKCU\...\Run）
run.bat --autostart-status   :: 看现在开没开、记的是什么命令
run.bat --no-autostart       :: 取消
```

- 自启项会记成**绝对路径**的 `pythonw.exe` + `main.py --background --detached`，并且**带上你当时用的 `--config` / `--log`**（有的话）。
- 写注册表在低完整性会话里会被系统拒绝（错误码 5），这是环境限制，不是程序坏了；本会话实测就是这种情况。
- 不想写注册表也可以：把 `run.bat` 的快捷方式丢进「启动」文件夹（`shell:startup`）。

### 6.3 想知道它是不是还活着

```bat
run.bat --doctor            :: 第 [0] 段会读状态文件，说实例在不在、pid、启动时间
type translate-ime.status.json     :: 实例每 5 秒心跳写一次
```

状态文件超过 `STATUS_STALE_SECONDS`（10 秒，两个心跳）没更新才算卡死；`--doctor` 会自动判断。

> 报告里会出现**两个 pid**，别把它们当成「两个实例」或者「实例在重启」：
> `[0] 进程号` 是常驻实例（不变），`[1] 诊断进程 pid` 是**正在跑体检的这个进程**（每次都换）。
> 第 120 轮起两行都写明了是谁。

## 7. 配置（`config.json`）

从 `config.example.json` 复制一份改名 `config.json`（或者 `--init-config`），改完**重启实例**生效。

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `hotkeys.quit` | `ctrl+alt+q` | 退出；空字符串 = 不设热键 |
| `hotkeys.toggle_enabled` | `ctrl+alt+z` | 挂起 / 恢复 |
| `hotkeys.toggle_direct` | 空 | 拼音 / 英文直通；空则只靠点 Shift（且 `input.shift_tap_toggles` 为真时） |
| `hotkeys.toggle_default` | `ctrl+alt+l` | 切换默认上屏语言 |
| `hotkeys.compose` | `ctrl+alt+space` | 一键直译上屏 |
| `input.shift_tap_toggles` | `true` | 点一下 Shift 是否切直通 |
| `input.shift_tap_ms` | `600` | 单击判定窗口（毫秒） |
| `output.tray` | `true` | 是否装托盘图标 |
| `output.log_file` | `translate-ime.log` | 日志文件；指到目录时在里面写默认文件名 |
| `output.start_enabled` | `true` | 启动时是「已启用」还是「先挂起」 |
| `translate.enabled` | `true` | 是否启用翻译（关掉后译文行不可用） |
| `api.provider` / `api.api_key` | — | 在线翻译的 provider 与 key；没配则走离线词表 |
| `input.commit_delay_ms` | — | 已废弃，写了只会得到提示、不生效 |

诊断配置：

```bat
run.bat --show-config     :: 打印当前生效的配置（api_key 打码）
run.bat --check           :: 只读自检：环境 / 系统输入法 / 热键 / 索引 / 翻译 / 窗口层
```

`--show-config` 的退出码只分两种情况：真有**拼错的键**才返回 1；整段写成标量
（`"hotkeys": 5`）这类**值写错**由开头的 `[config]` 那几行负责说明，退出码仍是 0，
它只在末尾附一句「另有 N 个键是整段类型写错」（第 122 轮之前这里会把值写错也算成
拼写错，还和 `[config]` 的计数对不上）。

## 9. 出问题时的自查流程（按顺序走）

### 第 1 步：`run.bat --check`

```bat
run.bat --check
```

- 退出码 0、最后一行「全部通过 ✅」= 环境层面没问题。
- 哪里是 `[FAIL]` 就按那一行说的问题修（比如翻译往返失败 = key 没配 / 网络不通）。
- 这一段还会打印「系统输入法」：告诉你本机装着哪些输入法、以及本工具不需要被选中。
- **有实例在跑时，报告会多一行「常驻实例」**：写着那个实例用的到底是哪份配置文件、退出键是什么（第 121 轮加）。
  如果你用 `run.bat --check --config 别的.json` 检查的是**另一份**文件，这里会给一条 `[warn]`——
  改文件要改实例正在用的那一份，否则改完按新热键不会有反应。

### 第 2 步：看症状，对症下药

| 症状 | 先跑 | 重点看 |
| --- | --- | --- |
| 双击 run.bat 后什么都没发生 | `run.bat --doctor` | `[0]` 段：实例在不在、状态文件是不是残留 |
| 敲字母没反应 / 不弹候选窗 | `run.bat --doctor` | 「键盘钩子」行和「候选窗」行：有效按键进没进钩子 |
| 字母被吞了但候选窗不出现 | `--doctor` | 候选窗那行会给出「有 N 个有效按键、候选窗一次没出现」 |
| 候选窗有、但上屏失败 | 看日志 | `[app] 上屏失败` — 文字会自动放进剪贴板，按 Ctrl+V 兜底 |
| 托盘图标没有 | `run.bat --tray-check` | 完整性级别、explorer、NIM_ADD 的真实错误码；低完整性下退出码 2。注意：`output.tray=false` 时它只说「托盘是你自己关的」并返回 0，不会去试装 |
| 热键按了没反应 | `run.bat --check` | 热键解析 / 撞车 / 动作名拼错会 `[FAIL]` 并说谁真生效 |
| 翻译不工作 | `--check` + 面板「翻译」行 | provider、失败次数、最近一次错误原文 |
| 开机没自启 | `run.bat --autostart-status` | 记下的 exe / 脚本还在不在、指向对不对 |
| 怀疑钩子被系统摘了 | `run.bat --doctor` | 「键盘钩子」行：重装次数、放弃重装、最近一个真实按键的时间 |

### 第 3 步：还查不出来，把这两个文件发给维护者

1. `translate-ime-doctor.txt`（`--doctor` 生成，逐项实测）；
2. `translate-ime.log` 里出问题前后那几十行。

### 第 4 步：实在不行就重来

```bat
:: 先退出（如果还活着）
taskkill /im pythonw.exe /f
:: 清掉运行痕迹（不会动你的配置和词库）
del translate-ime.status.json translate-ime.ctl translate-ime.log
:: 再启动
run.bat
```

## 10. 升级 / 卸载

- 升级：退出实例 → 覆盖程序文件 → 重新双击 `run.bat`。`pinyin_index.pkl` 缓存可以留着，也可以删掉让它重建。
- 卸载：
  1. `run.bat --no-autostart` 取消自启；
  2. `Ctrl+Alt+Q` 退出实例；
  3. 删除整个 `translate-ime` 目录（`config.json` 里有 API key，删之前想留着就自己备份）。

## 11. 已知限制（别去试）

- **语言栏里没有它**：设计如此（见第 11 节，以及 README 的「语言栏里为什么找不到它」一节）。
- **提权窗口打不进去**：以管理员身份运行的窗口收不到普通进程注入的按键（UIPI），需要本工具也用管理员身份启动。
- **全屏独占的游戏**里钩子可能收不到键。
- **安全软件**可能拦截全局钩子 / 注入，被拦时请把它加白名单。
- **热键冲突**：别的程序占了同一个组合键时，`--check` 会指出撞车；本工具不强行抢。
- 低完整性进程里**托盘装不上**（UIPI），这是系统限制；用控制面板兜底。
- 关闭启动黑框**不会**杀掉实例 —— 这是设计，不是 bug。
