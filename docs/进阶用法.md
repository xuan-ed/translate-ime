# 进阶用法与疑难排查

> 从主页搬出来的详细说明：语言栏、后台常驻、完整的已知限制、`--doctor` 怎么读。
> 返回 [项目主页](../README.md) · 第一次用先看 [使用流程](使用流程.md)。

## 语言栏里为什么找不到它（它不是系统输入法）

它不注册 TSF 文本服务，也不装键盘布局，所以 **Win+Space / 任务栏语言栏里永远不会出现它** —— 没有「选中它」这一步。启动之后它用一个全局键盘钩子接管字母，直接打拼音就行。

- **怎么确认它在干活**：随便找个能打字的窗口敲 `nihao`，候选窗会贴在光标下方弹出，空格上屏「你好」。没反应就先按 `Ctrl+Alt+Q` 退出、再跑 `run.bat --doctor`，报告里「键盘钩子」和「候选窗」两行会指出是哪一层没通。
- **它和微软拼音的关系**：本工具运行期间字母先被钩子拿走，微软拼音收不到这些键；但它照旧装在系统里，Win+Space 随时能切过去。想把手指还给系统输入法，按 `Ctrl+Alt+Z` 挂起即可（挂起时所有按键原样透传）。
- **想彻底不要微软拼音**：Windows 设置 → 时间和语言 → 语言和区域 →「中文(简体，中国)」→ 删除微软拼音；或者 Win+Space 只留「英语(美国)」。本工具不依赖任何系统输入法。
- **唯一打不进去的窗口**：以管理员身份运行的窗口 —— Windows 的 UIPI 会丢掉普通进程注入的按键，那种窗口需要本工具也用管理员身份启动。
- 托盘图标不是必需的：双击 `run.bat` 正常启动时它会出现；如果从低完整性进程里启动，托盘会被系统拒绝，跑 `run.bat --tray-check` 会说明原因，这时用「再双击一次 `run.bat`」弹出的控制面板来挂起或退出。

## 后台常驻

**双击 `run.bat` 就是后台常驻** —— 它会打印日志路径然后立刻返回，`pythonw.exe` 起来的那个进程没有窗口。**关掉那个黑框不影响输入法**（这一点以前是反的：前台跑的时候关掉控制台程序就死了，看起来就像"用着用着自己没了"）。

要是这台机器还没装依赖（`pypinyin` / `jieba`）或者还没建过索引，`run.bat` 会**当场把原因和装依赖的命令打出来**，然后停住等你按键 —— 不会再出现「黑框一闪、什么都没发生」。等 1.5 秒是为了确认后台那个进程真的活着，见踩坑第 39 条。

放在**带空格或中文的目录**里也一样：`Program Files`、`桌面`、`D:\我的软件` 这些路径都能直接双击 `run.bat` —— 索引、日志、状态文件、自启命令里的引号都按那个路径正确处理（`tests\test_path_handling.py` 把整个程序拷到 `…\输入法 路径 xxxx\带 空格 的 程序` 里真跑 44 项验证过：`--check`、`run.bat`、`--background` 常驻、真按键上屏「你好」、`quit` 退出）。

等价的手工命令，以及相关开关：

```bat
run.bat --background
```

`--background` 会立刻返回，真正的进程由 `pythonw.exe` 拉起。相关开关：

| 命令 | 作用 |
| --- | --- |
| `run.bat` | 后台常驻启动（参数原样转给 `main.py`，所以 `run.bat --background` 也一样） |
| `run.bat --foreground` | 反过来，留在前台看日志（`--foreground` 永远盖过 `--background`） |
| `run.bat --background` | 无控制台后台启动 |
| `run.bat --log D:\path\to.log` | 指定日志文件（默认 `translate-ime.log`，超过 2 MB 自动轮转成 `.1`）；指到目录（含 `D:\logs\` 这种写法）就在里面写 `translate-ime.log` |
| `run.bat --autostart` | 写进 HKCU 开机启动项；写不进去就退回往「启动」文件夹放 `.cmd`（都不需要管理员，两条路都实测过真能拉起实例）。同时带的 `--config` / `--log` 会一起记进自启项（相对路径会转成绝对路径），装完会打印「开机时执行」的那条完整命令行 |
| `run.bat --no-autostart` | 取消开机自启 |
| `run.bat --autostart-status` | 只看当前是否已开启自启 |
| `run.bat --check` | 自检：逐项检查运行环境、热键、词库、索引、翻译、窗口层（真的把候选窗建一遍再拆掉，建不出来就 FAIL）。有实例常驻时会写明它用的是哪份配置；`--config` 检查的是另一份时给 `[warn]`，免得你以为改的那份已经生效 |
| `run.bat --show-config` | 打印**每个选项的生效值和来源**（`[文件]`/`[默认]`/`[环境]`），并点名拼错的键；有拼错的键就退出码 1 |

> 前台跑也会写日志（控制台和文件同时写）—— 控制台一关就什么都不剩了，而你报"不灵了"的时候日志往往是唯一的线索。

常驻之后有三个入口：

- **再双击一次 `run.bat`** —— 检测到已经有一个在跑，它会**弹出一个小控制面板**（不需要托盘）：
  显示那个实例的进程号、是否已挂起、当前是拼音还是英文直通、上屏语言、托盘状态、**开机自启现在是什么状态**（已开启（注册表）/ 已开启（启动文件夹）/ 未开启 —— 这一项可能被系统悄悄退回启动文件夹，也可能压根没开成，不该让用户靠记忆去分辨）、**自学习记住几个词、这些权重有没有真的落盘**、**翻译层现在用的是在线 DeepSeek 还是离线词表、请求了几次、命中缓存几次、失败过几次（以及最近一次失败的原因）**、**键盘钩子收到了几个真实按键 / 吞掉了几个**、**候选窗显示过几次、落在哪块屏上**、日志路径，
  **CapsLock 开着的时候还会额外明说一句**「大写锁定 开（现在敲字母会直接打出英文大写，不弹候选）」—— 否则用户会以为输入法是坏的，见踩坑第 20 条，
  然后给你一个菜单：挂起/恢复、英文直通开关、换默认上屏语言、显示使用帮助、打开日志、打开配置文件、退出。
  选完会**重新读一次真实状态再显示**，所以你看到的是那个实例现在的样子，不是猜的。
  （想让它在后台一句话都不问：再双击一次 `run.bat`——它在非交互式控制台下会打印提示并直接以退出码 3 结束。）
- **托盘图标**（右键菜单）：启用/挂起、英文直通、上屏译文、当前状态、使用帮助、打开日志、打开配置文件、退出。
- **`Ctrl+Alt+Q`**：直接退出，不依赖托盘。

> 面板和托盘走的是**同一套命令**（`toggle_enabled` / `toggle_direct` / `toggle_default` / `help` / `open_log` / `open_config` / `quit`），
> 实现方式是运行中的那个实例把状态写进 `translate-ime.status.json`（状态有变化就写，没变化也**每 5 秒写一次心跳** ——
> 外面靠这个文件的 mtime 判断那个实例是活着还是卡死了，不写心跳的话「闲着不打字」会被误报成「卡死」，见踩坑第 17 条），
> 控制面板往 `translate-ime.ctl` 里追加一行命令。
> 用文件而不是 IPC，是因为这样不需要常驻一个服务端，也能脱机测试。这两个文件都在 `.gitignore` 里。

> 单实例保护：如果已经有一个在跑，第二次启动不会再装一个钩子上去
> （两个进程各装一个低级键盘钩子会互相抢键，表现是「有时候有候选、有时候没有」）。

> 注意：日志文件是 UTF-8。用 PowerShell 看要加 `-Encoding utf8`（`Get-Content translate-ime.log -Encoding utf8`），
> 否则它默认按 GBK 读，中文会显示成乱码。

## 已知限制

- **只有 Windows。** 换平台要重写 `winapi.py` 整个模块。
- **没有注册进系统 IME 列表。** 这是刻意的（不改系统设置），代价是：某些用 TSF/IME API 深度集成的程序（个别游戏、部分 Electron 应用的富文本框）里可能表现异常。
- **需要出站 HTTPS。** 翻译要访问 DeepSeek 接口；公司网络/代理环境记得配好代理。
- **翻译有网络延迟。** 候选窗会先显示中文、译文随后补上；译文没回来时按空格上屏的是中文，并会在窗里提示原因。
- **光标准确定位依赖目标程序提供 caret 信息。** 拿不到时会退回鼠标位置（`GetGUIThreadInfo` 对很多程序返回不了 caret）。
- **托盘图标在低完整性进程里装不上。** `Shell_NotifyIconW(NIM_ADD)` 会返回 `ERROR_ACCESS_DENIED(5)`：UIPI 拦下了完整性级别低于 `explorer.exe` 的进程发给托盘窗口的消息。正常双击 `run.bat`（中完整性）没这个问题；但在被降权的沙箱/容器里跑就会有 —— 这时程序不会崩，只是打不开托盘菜单，会往 stderr 和日志里写明原因。
- **开机自启同样受完整性级别限制。** `--autostart` 先写注册表 `HKCU\...\Run`，写不进去就退回往「启动」文件夹放一个 `.cmd`；两条路都被拒绝时命令会以退出码 1 失败，并打印**具体是哪种拒绝**（而不是笼统的「失败」）。在被降权的环境里请改用正常终端执行。两条路的产物都实测过：注册表项就是一条完整命令行（`"…pythonw.exe" "…main.py" "--background" "--detached"`），直接照它拉起进程就能起来（第 24 轮又实测了一遍，并把「这两条载荷真能拉起一个装了钩子的实例」变成了 `tests/test_autostart.py` 第 6b 节的护栏 —— 见踩坑第 14 条）；退回的 `.cmd` 里含一行 `chcp <代码页>` 把自己的编码和 cmd 的解析代码页对齐（不这么做时中文路径会被 cmd 读成 `锟接伙拷`，自启静默失效，见踩坑第 14 条）。
- **「打字没反应」有四种完全不同的原因，别忘了先看状态。** 单击 `Shift` 进的是「英文直通」（字母原样输入、**不弹候选窗**），`Ctrl+Alt+Z` 是挂起（所有键都透传）。这两种状态现在都会在**连打 3 个字母后**在候选窗上提醒一次 —— 因为在此之前它们是完全静默的，用户只会以为程序坏了。第三种是钩子压根没收到你的键：**双击一次 `run.bat`**，控制面板里那行「键盘钩子」会直接告诉你收了多少个**有效按键** —— `还没收到过真实按键` 就说明问题在钩子这一侧，`收到过 N 个有效按键` 就说明键进来了、该往下游查。第四种最反直觉、而且换台电脑就复现不了：**机器上装了改键器/宏软件**（PowerToys Keyboard Manager、AutoHotkey、罗技雷蛇驱动、笔记本快捷键工具、软键盘）时，你手敲的每个键都会被它们转发，转发出来的事件带 `LLKHF_INJECTED` —— 早期版本把这类事件当自激全部丢弃，表现就是打字完全没反应；现在**别人转发的注入会被当成真实按键处理**，控制面板会写「其中 N 个是别的程序转发的（改键器/宏/软键盘，已按真实按键处理）」（细节见踩坑第 11 条）。想更细就 `python main.py --hook-check`（它会请你敲几个字母并把结果直接说出来），它的退出码是固定的五档：`0` 真看到了按键、`5` 连全局键盘钩子都装不上（安全软件或权限拦了 `WH_KEYBOARD_LL`，屏幕上会写原因）、`6` 那几秒里一个真实按键都没收到、`7` 钩子装上了却立刻不生效（自检按键也没回来）、`8` 没抢到前台窗口、注入式自检做不成，**或者已经有一个实例在常驻**（它的钩子先装上、会把字母吞掉，这时量到的数字没有意义 —— 先退出那个实例再跑；这两种都归在 8 里，因为对你来说都是「这次没做成」）（这五档都有测试覆盖，`0` 那一档用「别的程序转发」的注入键模拟改键器）。拿不准就先跑 `python main.py --doctor`，它会把上面每一条逐项实测一遍。
- **改了 `config.json` 却毫无反应？先跑 `run.bat --show-config`。** 五种最常见的原因：① 文件被存成了**带 BOM 的 UTF-8**（PowerShell 的 `Out-File -Encoding utf8`、某些编辑器），整份配置会被忽略、全部退回默认值（见踩坑第 12 条）；② 键名拼错了，那个键被静默忽略（`--show-config` 会点名，退出码 1）；③ 文件根本不是合法 JSON（多一个尾逗号、少半个引号），或者顶层写成了数组 —— 整份配置会被忽略、全部退回默认值，启动时和 `translate-ime.log` 里都会明确说这一句（见踩坑第 49 条）；④ 那个选项是**从旧模板里留下来的、从来没接上的**（早年模板里的 `input.commit_method` / `input.commit_delay_ms`），启动时和日志里会点名说「从旧模板留下的选项，从来没生效过，已从模板删掉」（见踩坑第 51 条）；⑤ **类型写错了**（`"dict_cache": 5` 把数字当路径、`"bg": 5` 把数字当颜色、`"default_language": "jp"` 写了不认识的取值），以前会直接崩在启动那一刻或静默按默认跑，现在逐项点名并退回默认值（见踩坑第 52 条）。它还会告诉你哪几个选项根本没写、正在用默认值 —— `init_config()` **绝不覆盖**已存在的配置，所以老配置文件不会自动长出新键。
- **候选窗按「光标所在那块显示器」避让，也按那块屏的缩放比重算字号。** 多显示器下窗口会正确地夹在光标那块屏的工作区里（不会被主屏宽度顶回主屏，也不会被任务栏吃掉一截）；逐屏 DPI 现在也是跟着走的：每次定位都问一次光标所在显示器的 DPI（`GetDpiForMonitor`，取当前生效值），和当前缩放比不同就销毁重建控件、按新比例重算字号/边距/宽度上限，然后把正在显示的内容重画一遍。以前只在启动时取一次主屏缩放比，副屏字号会偏小或偏大（见踩坑第 44 条）。
- **「双击了 `run.bat` 却什么都没发生」这类残留问题会自愈，不用手动删文件。** 上一个实例被强杀、崩溃、注销或断电干掉时，它来不及清理的状态文件与命令收件箱会留在磁盘上；新实例启动的第一件事就是把它们丢掉（并把丢掉的内容写进日志），所以不会出现「上次留下的 `quit` 把这次的新实例带走」这种怪事（见踩坑第 13 条）。`--doctor` 说「状态文件是残留的」也只是提示，不影响使用。

## 出问题先跑这一条

```bat
run.bat --doctor
run.bat --show-config   :: 改了配置却没反应时跑这条
```

它把「你机器上才有的情况」逐项变成一行实测结论：**正在跑的那个实例**（进程号、状态文件是否还在刷新、**候选窗到底显示过几次、有没有落在屏幕上**、**钩子收到过几个真实按键、吞掉了几个**、主循环报过几次错）、完整性级别、shell 与托盘图标能不能装、配置与热键、日志能不能写、全局键盘钩子能不能装、**候选窗到底有没有落在屏幕上**、以及钩子 → 状态机 → 候选窗 → 上屏整条链路能不能跑通。每行是 `[ok ]` / `[warn]` / `[FAIL]` / `[info]`，报告同时写到 `translate-ime-doctor.txt`，**那整个文件可以直接贴给我**。有 `[FAIL]` 时退出码为 1（`[warn]` 不算）。

`[0]` 那一段尤其有用，它用两句话就把「打字没反应」切干净了：**候选窗**那行报「启动至今一次都没显示过」就是「候选窗根本不出现」的直接证据（跟键盘、跟拼音无关，问题在窗口这侧）；**键盘钩子**那行报「还没收到过真实按键」则相反 —— 键压根没进钩子，问题在钩子这侧（实例刚起来、你还没敲过字时也会这么显示，那不是故障；`--no-hook` 起的实例会直接写「没安装」）；只有「收到了 N 个有效按键」+「显示过 M 次」同时成立，才说明两条腿都在，该往状态机 / 上屏那一段查。上一轮实例如果是被强杀/崩溃干掉的，`[0]` 不会拿它留下的状态文件把**死进程**报成活的，而是明说「状态文件是残留的：进程 N 已经不在了」并跳过那些只对活实例有意义的行 —— 下次双击 `run.bat` 就会自动覆盖它、并丢掉残留命令（见踩坑第 13 条）。

加 `--doctor-quick` 会跳过「试装托盘 / 真装钩子 / 端到端」这三项要动系统的检查，两秒内出结果（`--doctor-quick` 与 `--doctor-seconds 15` 都可以**单独敲**，不用再带 `--doctor`；反过来 `--hook-check-seconds` / `--demo-seconds` 脱离了 `--hook-check` / `--demo` 会直接报错退出 —— 这种「修饰参数单独出现」以前会被静默忽略、然后程序照常启动，见踩坑第 31 条）；加 `--doctor-seconds 15` 会额外开一个 15 秒的窗口，请你在这段时间里真敲几个字母，用来看钩子**到底收不收得到你的按键**（这是唯一无法自动验证的一项）。

## 打包成 exe（维护者用）

**双击 `translate-ime.exe` 等于双击 `run.bat`**：后台常驻 + 弹出设置窗口。打包版没有 `run.bat` 可点，用户点的就是 exe 自己，所以 `main.py` 会在 `frozen` 且一个参数都没给时把命令行补成 `--background --panel` —— 补出来的开关只用于本次启动，不会被写进开机自启项（否则每次开机都弹窗）。

同一个入口还兜了两件打包版特有的事：`console=False` 的进程没有控制台，`sys.stdout` / `sys.stderr` 都是 `None`，`print` 一下就会 `AttributeError`，所以入口先把它们换成空流；另外「已经有一份在跑」时也照样把窗口开出来（用户第二次双击的动机通常就是找入口）。

发版不用手动敲命令：**推一个 `v*` 开头的 tag，GitHub Actions 会自己打包并挂到 Release 上。**

```bat
git tag -a v0.1.1 -m "v0.1.1"
git push origin v0.1.1
```

几分钟后 Releases 里就有 `translate-ime-windows-x64-v0.1.1.zip`。想先看构建过不过、又不发版，去 Actions 里手动 Run workflow（`release_tag` 留空就只出 Artifacts）。

产物是 **onedir**（一个文件夹，不是单文件 exe）：onefile 每次启动都要把几十 MB 解压到临时目录，冷启动明显更慢，杀软也更容易拦。文件夹里有三个东西：

| 文件 | 说明 |
| --- | --- |
| `translate-ime.exe` | 窗口版（`console=False`），双击用它 |
| `translate-ime-cli.exe` | 控制台版，`--check` / `--doctor` / `--build-index` 的输出只有它看得见 |
| `_internal\` | 依赖、`webui.html`、托盘图标、`jieba` 的词库、`config.example.json` |

**冻结之后有两套目录，这是打包唯一真正需要小心的地方**（`t_ime/paths.py`）：

- `app_root()` = **exe 所在目录**，可写。`config.json`、日志、`pinyin_index.pkl`、`user_boosts.json`、状态文件和命令收件箱全在这儿 —— 所以「解压到 Program Files」是不行的，那儿不给写。
- `bundle_root()` = `sys._MEIPASS`，只读，放资源和模板。

连带改掉的几处：`pythonw_path()` 在冻结时返回 exe 自己、`background_command()` 不再拼 `main.py`（后台常驻就是「再跑一次 exe，加 `--background --detached`」），`panel.panel_argv()/start_argv()` 同理 —— 否则双击 exe 后「再开一个设置窗口」「提权重启」都会去执行一个根本不存在的 `main.py`。开机自启项在冻结状态下变成「exe + 参数」，`autostart_problem()` 也认这种形状（换个目录摆的副本会被点名）。

本地想自己打一次：

```bat
.venv\Scripts\python.exe -m pip install pyinstaller
.venv\Scripts\pyinstaller.exe --noconfirm --clean translate-ime.spec
```

打完先跑 `dist\translate-ime\translate-ime-cli.exe --check` —— 冻结后最容易坏的几件事（词库没打进去、索引写到只读目录、`_internal` 被单独拷走）它都会当场说出来。
